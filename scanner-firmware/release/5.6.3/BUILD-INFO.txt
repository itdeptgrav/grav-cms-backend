NETWORK / RESPONSIVENESS CHANGES
--------------------------------
  1. onWiFiConnected() returns immediately (was ~25s inline)
  2. serviceReconnectFollowUp() state machine, one phase per loop pass
  3. queueTimesPending holds the sender until timestamps are reconstructed
  4. handleServerUpdateBarcode() disowns in-flight OLD-server tasks
  5. noteBackendResult() transition logging + repaint flag; rejects a success
     landing after the link dropped
  6. loop() repaints on a known state change, not only the 1s tick
  7. Reconnect spacing 3s / 10s / 30s (was flat 30s)
  8. Update availability check + machine-name fetch moved into ONE background
     task (updchk). Neither blocks the scanning loop any more.
  9. Result handed back core0 -> core1 through a FreeRTOS queue by pointer
     ownership transfer, not a volatile flag over shared Strings.
 10. Setup portal scanner port derived from DEFAULT_SERVER_PORT
 11. Send and heartbeat tasks now use a URL snapshot composed on core 1 and
     carried in their own SendJob, so no task reads serverScheme/serverHost
     (mutable Strings) from core 0 during an SRV: re-point.
 12. startUpdateCheck() drains any stale result from the one-deep mailbox
     before spawning, so a disowned task cannot cost the next run its slot.
 13. FW_VERSION 5.6.2 -> 5.6.3

  OTA INSTALL (performOTAUpdate) is byte-identical and still blocking, by design.
